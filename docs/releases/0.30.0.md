# ManiOS 0.30.0 — installer, profiles and dependencies (in progress)

0.30.0 brings a Debian-style installer with profiles (desktop, server,
server with DOS, custom), a data partition and offline packages from the
CD: [ADR-0011](../adr/0011-debian-style-installer.md). This page grows as
the parts land.

## Done so far

- **`pkg` dependencies:** `requires` lines in the index; `pkg install`
  installs what a package needs first, `pkg remove` refuses to remove
  what an installed package needs (`-f` to force).
- **ManiDOS as a package:** `manidos` (`dos`, `dosrun`), a native package
  built from this tree. Every DOS package requires it. Where ManiDOS is
  built into the system (`/boot/bin`), `pkg` counts it as installed and
  never downloads it.
- **Groups:** `group` lines in the index; `pkg install @dos-tools`.
- `tools/mkrepo.py`: native packages from the build, `requires`, groups.
- Older `pkg` (0.29) reads the new index and ignores what it does not know.
- **The base system:** `build/base/manios-base.bin`, the same kernel and
  programs without ManiDE (`manide`, `desktop`, the desktop apps) and
  ManiDOS (`dos`, `dosrun`, `AUTOEXEC.BAT`): 1.42 MB instead of 1.87 MB.
  The ISO carries it as `BASE.BIN` for the installer; the live CD still
  boots the full system. The boot message suggests only what is there
  (`pkg` instead of `manide` and `dos`).

- **ManiDE as a package:** `manide` (ManiDE, `desktop`, and the desktop
  programs, with its session file in `share/manide/session`, which ManiDE
  reads when there is no `/boot/etc/manide`). Built in on the full system.
- **Installing without a network:** `pkg -u DIR` takes a directory as the
  repository, such as the install CD's `/n/CD/REPO`, with the same
  signature and SHA-256 checks; there a package may be `PKGS/NAME.TAR`.
  `mkrepo.py --cd DIR` writes that copy (8.3 names, sources in `SRC/`), and
  `make iso CD_REPO=DIR` puts it on the ISO (about 6 MB; the ISO is then
  9.8 MB). Without `CD_REPO` the ISO has no repository, as CI builds it.
- `tools/mkiso.py`: subdirectories (`--dir NAME=DIR`), directories larger
  than a sector, full path tables; directory entries now sorted by name
  as ISO 9660 asks (BOOT.CAT used to come first).
- `pkg` handles up to 16 commands per package (was 8).
- **The installer** ([docs/install.md](../install.md)): `install` with no
  arguments asks step by step (keyboard, network, host name, disk,
  profile, packages, summary); `--profile desktop|server|server-dos|custom`,
  `--pkg`, `--hostname`, `--net`, `--dns` and `--repo` do the same from a
  script. It writes the base system and a FAT16 data partition (up to
  2 GiB) holding `SETUP.CFG` and, from a release CD, a copy of the signed
  repository, so the CD can come out at once. `install DISK KEY=VALUE`
  works as before.
- **`setup`** runs at every start of an installed system
  (`/boot/etc/rc.setup`): the first time it installs the profile's
  packages, cleans up and restarts once; later it runs `manios/etc/rc`.
- **`mkfat`** makes FAT16 file systems (2 MiB to 2 GiB), on a partition
  or a range of a disk. `setup`, `mkfat` and `rc.setup` are in the base
  system only: the full system (the live CD) does not need them, and the
  smallest machine it starts on stays 7 MiB.

## Known limits

- The full system needs 7026 KiB of the 7040 KiB a 7 MiB QEMU machine
  offers: 14 KiB to spare. The next growth of the live system makes 8 MiB
  its minimum, unless something moves out of it (as `setup` and `mkfat`
  did).
- The data partition is FAT16: at most 2 GiB, 8.3 names.
- ISO with the package repository: built locally (`make iso CD_REPO=...`),
  as the repository is signed with a key CI does not have.

## Tests

- `tests/installer_test.py` (in `make test`): from the ISO, `install
  --profile server` writes the base system and a data partition that the
  host's mtools and fsck.fat read; the disk boots alone, `setup` finishes
  once and not again, the host name is set, there is no ManiDE or
  ManiDOS; refusals; `mkfat` on part of a disk passes fsck.fat.
- On QEMU's BIOS with a release-style CD (signed `REPO`), outside the tree:
  each profile installed onto a blank 64 MiB disk, then booted from the
  disk alone, with no CD and no network. Desktop: setup installed `manide`
  and `manidos`, removed the copies, restarted, and the second start was
  ManiDE with its session. Server: no packages, no restart, no DOS.
  Server + DOS with `--pkg unzip`: ManiDOS, the 15 DOS tools and unzip,
  and FIND found a line. The interactive installer, answered step by step
  (server, host name, `zoo`): installed as chosen (4 of 4).

- `tests/base_system_test.py` (in `make test`): the base archive is the
  full one minus ManiDE and ManiDOS, the ISO carries `BASE.BIN`, and the
  base kernel boots without `dosrun` and `manide` but with `pkg`.
- With the signed repository (outside the tree, it needs the key): on the
  base system `pkg install arj` installed `manidos` first, arj made and
  listed an archive through the installed `dosrun`, `pkg remove manidos`
  was refused while arj was installed, and after a reboot arj still ran
  and both packages were removed. On the full system `manidos` counts as
  built in, `@dos-tools` installs the group, and `requires` puts
  dependencies first (43 checks).
- Offline, outside the tree (it needs the signed repository): the base
  kernel with the CD (`CD_REPO`) and no network card found `REPO` on the
  CD, read the signed index, installed `manide` and `arj` (with
  `manidos`), arj ran, ManiDE from the package started its session
  (`term fetch`, `welcome`, `term top`), and a directory whose index had
  no valid signature was refused (6 checks).
