# ManiOS 0.29.1 — FIND and UnZip in the repository

A small update to 0.29.0: a DOS fix that lets FreeDOS FIND run from a
package, and two more packages in the repository at
<http://manios.nl/repo/>.

## Repository

- **find** — FreeDOS FIND 3.0b (GPL-2): search for text in files.
  `find target C:/NOTES.TXT`, `find /I /V word FILE.TXT`.
  Needs ManiOS 0.29.1 or later (see the fix below).
- **unzip** — Info-ZIP UnZip 6.00, the 16-bit DOS build (Info-ZIP licence),
  with `funzip`. List, test and extract `.zip` archives:
  `unzip -l A.ZIP`, `unzip -t A.ZIP`, `unzip -o A.ZIP -d C:/OUT`,
  `unzip -p A.ZIP FILE`. Works on 0.29.0 too. FreeDOS 1.4 ships the
  32-bit DJGPP build, which needs DPMI, so the package is built from
  Info-ZIP's own DOS release and published with Info-ZIP's source archive
  (`src/unzip-6.00.tar.gz`). Its launcher sets `TZ=UTC0`.
- The repository now has 27 packages. `tools/mkrepo.py` accepts a
  self-extracting `.exe` zip as the upstream package and a separate
  `source` archive.

## Fixed

- **dosrun, INT 21h AH=0Eh (select drive):** the drive number was read from
  AL instead of DL, so any program that selected a drive was sent to A:
  (FreeDOS FIND looked for relative names there). The drive now comes from
  DL; an unmounted drive leaves the current one selected; AL returns the
  number of drive letters (26). `tests/dosrun_device_test.py` checks it.

## Tests

- End-to-end in QEMU (`pkg` from a local copy of the repository): all 27
  packages install; FIND finds lines by absolute and relative path, with
  `/I /V`; UnZip lists, tests, prints and extracts `KNOWN.ZIP` (the
  extracted file matches byte for byte); `funzip` prints the first member;
  removal, reboot persistence and tamper refusal as in 0.29.0.
