# ManiOS 0.28.0 — DOS compatibility update

0.28.0 makes more DOS software run under `dosrun` by modelling more of the
PC that programs probe or program directly, and re-verifies the existing
compatibility list on the new build.

## What changed in dosrun

Full contract: [dosrun.md — Hardware and CPU model (0.28.0)](../dosrun.md#hardware-and-cpu-model-0280).

- **VGA registers.** CRT controller (3D4h/3D5h) with live cursor shape,
  cursor position and page start; DAC palette ports (3C6h–3C9h) and the
  INT 10h palette calls; attribute controller (3C0h/3C1h); VGA display
  identification (INT 10h AX=1A00h, AH=12h BL=10h). Mode 13h graphics are
  now drawn through the program's palette instead of a fixed RGB 3-3-2 map.
- **Real clock.** The CMOS clock (70h/71h), INT 1Ah and the DOS date read
  ManiOS's wall clock. The DOS date had been fixed at 2026-10-07.
- **Absent hardware is reported as absent.** No numeric coprocessor (ESC
  and FWAIT behave as on a PC without one, so programs fall back to their
  own floating-point emulation), no joystick, no Sound Blaster/AdLib.
  Keyboard LED/typematic commands on port 60h are acknowledged.
- **CPU.** FS/GS segment registers, LSS/LFS/LGS, INT3, SMSW, word port
  I/O, and correct LOCK/ARPL handling. `MOV` to segment registers 4–7
  previously corrupted ES/CS/SS/DS; FS/GS now work and invalid forms are
  refused.
- **Interrupt vectors.** BIOS/DOS-range vectors without a handler point at a
  ROM stub instead of 0000:0000, as on a PC; programs that chain or call
  through them still reach dosrun's service for that interrupt.
- **XMS fixes.** The XMS entry stub no longer overwrites program memory
  (it was written at `PSP:FE00`, inside large EXEs such as SemWare TSE),
  and INT 2Fh no longer answers non-XMS multiplex calls as XMS.
- **DOS.** TRUENAME (AH=60h); invalid drives in AH=36h; terminate-and-stay-
  resident (AH=31h, INT 27h) now ends the program cleanly. The switch
  character call (AH=37h) is intentionally still refused so that
  `C:/FILE` arguments keep working.

New regression: `tests/dosrun_device_test.py`. Updated expectations in
`dosrun_port_test.py` and `dosrun_cpu_audit_test.py` (FS/GS and word reads
of 3DAh are now supported).

## Compatibility results

The catalogue still has 200 programs: **91 Working, 40 Partial, 54 Broken or
unsupported and 15 Untested** (0.27.0: 83 / 27 / 75 / 15). Working + Partial
rises from 110 to 131 (65.5%). Per-program results are in
[dos-compatibility.md](../dos-compatibility.md).

- **Re-verified:** the 82 programs still listed as Working were re-run with
  scripted workflows on this build — output text and the bytes they write
  were checked ([results](../compatibility/2026-11-22-028-working-retest.json)).
- **New Working (9):** @Compare, CQvert, CHOP, EVAL, CALC 1.00, Bali's Calc,
  CPUID, SYSID and GW-BASIC.
- **New Partial (13):** As-Easy-As, DOSINFO, MEM 3.0, NUMCONV, Hanoi,
  TypeFast, PC-Calc, Directory Maven, CHAMP Galagon, Dr Mind Lite, Galaxy
  Lite, PC-File and ANA.
- **Corrected:** CYLON4 was listed as Working, but its 2026-10-25 run had
  stopped on a VGA port. It is a TSR, and nothing stays resident after
  dosrun exits, so it is Unsupported.
- Many still-unsupported programs now stop later with a new, recorded reason
  (CWSDPMI/DPMI extenders, DOS 5 requirement, VGA graphics controller,
  diskette controller). Details:
  [targeted retest](../compatibility/2026-11-22-028-targeted-retest.md).

## Known limits

- No protected mode/DPMI: DJGPP/CWSDPMI, DOS/4GW and DOS/32A programs
  remain unsupported.
- No x87 arithmetic: programs that require a coprocessor without checking
  for one will not compute correctly.
- No resident programs (TSRs).
- AH=36h free-space figures are still placeholders.
- Some programs accept input only through the serial console, not the
  emulated PS/2 keyboard (As-Easy-As, Adventure); NUMCONV and PC-Calc
  ignore part of their input on both paths.
